# docker-dev-embedded-arm

ARM Cortex-M development container for bare-metal C++. Covers **STM32**, **RP2040**, **TI MSPM0C1104**, and any other Cortex-M target. No HAL or vendor SDK — bring your own linker script, startup file, and SVD.

Inherits from `docker-dev-embedded-base` which provides all probe tools (openocd, BMP, probe-rs, st-link, picotool, wlink).

## What this image adds

- `arm-none-eabi-g++` (C++20, bare metal, newlib)
- CMSIS_6 headers at `/opt/cmsis` (`$CMSIS_DIR`)
- CMSIS-DSP pre-built library at `/opt/cmsis-dsp` (`$CMSIS_DSP_DIR`), built for Cortex-M4F
- 5 ARM-specific Claude skills (startup, vector table, FPU, MSPM0 quirks, CMSIS-DSP)

## Quick start

```bash
# 1. One-time host setup (first time only)
sudo ./scripts/install-host-udev-rules.sh   # from docker-dev-embedded-base
sudo usermod -aG dialout,plugdev $USER       # log out and back in

# 2. Plug in your probe (ST-Link or BMP)

# 3. Build and start the container
./scripts/dev-up.sh /path/to/your/firmware

# 4. Inside the container, set up a new project
/scaffold-mcu-project arm

# 5. Edit .mcu-profile.json — set OPENOCD_TARGET to match your chip
#    STM32F4:   target/stm32f4x.cfg
#    STM32G0:   target/stm32g0x.cfg
#    RP2040:    target/rp2040.cfg
#    MSPM0:     target/ti_mspm0.cfg

# 6. Build (Ctrl+Shift+B in VSCode, or inside the container):
/opt/embedded/run-profile-task.sh build
```

## Project requirements

Each project in this container must supply:
- **Linker script** (`*.ld`) — defines MEMORY regions for your specific chip
- **Startup file** (`startup.cpp` or `startup.s`) — initialises `.data`/`.bss`, calls `__libc_init_array`, then `main()`
- **CMake toolchain file** (`cmake/arm-none-eabi.cmake`) — generated by `/scaffold-mcu-project arm`
- **SVD file** (optional but recommended) — decoded by the Peripheral Viewer in VSCode debug sessions

See the `cortex-m-startup-cpp` Claude skill for the correct C++ startup pattern.

## Probes

| Probe | Interface config | Target config example |
|---|---|---|
| ST-Link v2/v3 | `interface/stlink.cfg` | `target/stm32f4x.cfg` |
| BMP (openocd) | `interface/cmsis-dap.cfg` | any target |
| BMP (native) | Use BMP config in launch.json | no openocd needed |
| Picoprobe | `interface/cmsis-dap.cfg` | `target/rp2040.cfg` |
| XDS110 (TI) | `interface/xds110.cfg` | `target/ti_mspm0.cfg` |

Run `/probe-detect` inside the container to identify what is connected.

## CMSIS-DSP

Pre-built for Cortex-M4 with FPU. For other cores, rebuild:
```bash
cd /opt/cmsis-dsp
cmake -S . -B build_m0plus \
    -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/aarch32-gcc.cmake \
    -DCMSISCORE=/opt/cmsis/CMSIS/Core/Include \
    -DARM_CPU="cortex-m0plus" -DFPU=0 -G Ninja
cmake --build build_m0plus --target CMSISDSP -j$(nproc)
```

See the `cmsis-dsp-cpp` Claude skill for linking and calling the library from C++.

## Template update propagation

This image tracks `ghcr.io/wojtacz/docker-dev-embedded-base:latest`. `dev-up.sh` passes `--pull` by default. CI rebuilds automatically via `repository_dispatch` from the base image.
